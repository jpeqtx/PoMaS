## 2. 絶対厳守ルール（違反禁止）
### 2-1. 指示の優先順位
「待て」 > 「整理しろ」 > 「機能実装を先にやれ」 > 「コンパイルしろ」

### 2-2. コンパイル指示の禁止
- ユーザーが「コンパイルしろ」「ビルドした」と明示するまで Ctrl+R を提案しない
- パッチ提示後に「結果を貼ってください」「Ctrl+Rしてください」を書かない
- パッチ提示はパッチのみで完結させる

### 2-3. コマンド出力仕様
- 各コマンドに `# [N/M] 短い説明` タイトルを必ず付ける
- 1コマンド=1行で完結（if/elseif/else の複数行分割は構文エラーになるため禁止）
- ヒアストリング `@'...'@` 単一引用符、`$b -replace "`r?`n","`n"` で改行統一
- 1回の提示で最大4個（2KB×4以下、巨大ヒアストリングでターミナルクラッシュ回避）
- 「実行してください」「次のステップ」等の定型文を書かない

### 2-4. 「待て」「整理しろ」遵守
- 「待て」→ 即座に完全沈黙、次の指示まで何も出さない
- 「整理しろ」→ 表のみ、コード出力禁止、勝手に実装しない

### 2-5. 高精度化省略の禁止
カテゴリ1〜10 の全項目を実装対象。部分的に実装する場合は「部分完了」と明記する。
## 3. コマンド出力の技術仕様
### 3-1. アンカーの取り方
- ファイルは LF 改行、CRLF なし、BOM なし
- アンカーに `\r\n` を含めない。必ず `` `n `` を使う
- 変更前に `$t.Contains($anchor)` で存在確認
- 置換は `$t.Replace($old,$new)` → `[System.IO.File]::WriteAllText($f,$t)`
- 検証: `$crlf=([regex]::Matches($t,"`r`n")).Count; $lf=([regex]::Matches($t,"(?<!`r)`n")).Count` → CRLF=0

### 3-2. マーカー方式（大きな挿入を安全に分割）
- 挿入先に `    //@XYZ_START@` マーカーを最初に置く
- 各ブロックは `$t.Replace($m, $m + "`n" + $b)` で挿入
- 最後に `$t.Replace("    //@XYZ_START@`n","")` でマーカー削除
- 残存確認: `$t.Contains("//@XYZ_START@")` が False

### 3-3. ヒアストリングと日本語
- `@'...'@`（単一引用符）で変数展開回避
- 中に `@'` を含めない
- 日本語ヒアストリング混在はターミナルクラッシュ要因 → 混在時は特に短く分割
- 落ちた場合 `chcp 65001` を先に実行

### 3-4. 検証パターン
- 関数存在: `$t.Contains("bool doXxx(")` / `$t.Contains("void doXxx(")`
- クラス数: `([regex]::Matches($t, 'class X \{')).Count` が 1
- dispatch: コマンド名をループで `$t.Contains('eqIC(cmd, "'+$c+'")')`
- マーカー: `$t.Contains("//@XYZ_START@")` が False

### DimVec（SciRef private、7次元）
    struct DimVec {
      int8_t d[7];    // L, M, T, I, Th, N, J
      operator+/operator-/scale(n)/isDimless/toString
    };

### Quantity
    struct Quantity { double v; DimVec dim; };

### unitDimDB（48単位）
    struct UnitDim { const char* name; double scale; DimVec dim; };
    例: {"km",1000,{1,0,0}}, {"N",1,{1,1,-2}}, {"J",1,{2,1,-2}}

### lawCalcDB（15法則）
    struct LawCalc { const char* name; const char* v; const char* f[4]; };
    例: {"Newton 2nd: F = m*a", "Fma", {"m*a", "F/a", "F/m", ""}}
    v は対象変数文字列、f[i] は v[i] を解く式。

## 10. ハードウェア制約と対策

### 10-1. 画面 (240x135, Font0=6x8px)
- 行間 11px を基本、履歴・上付き累乗は 13px に拡張
- 上付き累乗は y-3 で描画（y-4 は前行と重なる）
- drawNatural / drawFrac2D は境界チェック（LCD_W-4）必須
- メニュー行高 13px、本文行高 11px

### 10-2. PSRAM なし (RAM 320KB)
- 大きな配列は global static（heap に置かない）
- ExprEval::Subst は 4要素程度に抑える
- String は短命、長寿命は char[] にコピー
- stat[] は ps_malloc フォールバック（PSRAM なし時は malloc）

### 10-3. キーボード
- `;` `.` `,` `/` は方向キー扱い（fn 併用）
- `<` `>` は shift+, / shift+. でカーソル移動
- ESC = バッククォート
- fn+数字 = メニューショートカット

### 10-4. 行間と文字列長
- メニュー項目は 26 文字以内（240px / 6 - インデント）
- 長い式は drawWrapped（最大 38 文字/行）を使う

- xcalc: ドイツ教育課程の Kurvendiskussion（交点/極値/変曲点/対称性/単調性/極限の自動解析）に特化。スプライトバッファリングで描画が滑らか。教育用途では PoMaS を上回るが、汎用数学・統計・数値計算は非搭載。
- PicoRuby Calculator: Ruby REPL によるプログラミング学習に最適。テーマ切替（Sakura/Cyber Retro/Editor）で見た目が良い。数値計算ライブラリは PoMaS が圧倒。Cardputer ADV 対応済み。
- CalcPuter: 数式評価 + 12公式 + 分数入力モード + Fnキーショートカット。関数電卓としての完成度は高い。README にスクリーンショット付きで実績あり。
- UcPlayground: 個別完成品ではなく実験ビルド集のため比較対象外。
- Zenn記事: 入門記事。機能比較対象外。
### 17-4. PoMaS の優位性（他プロジェクトに対する）
1. 機能の網羅性: 10カテゴリ 53項目超。他プロジェクトは単一目的（CAS特化、REPL特化、関数電卓特化）。
2. 統合度: 電卓/CAS/統計/医学/グラフ/表計算/プログラミング/次元解析を1ファームウェアに統合。Cardputer の「持ち運べるワークステーション」コンセプトを最も体現。
3. 実装の深さ: CAS 34コマンド、適応シンプソン積分、Richardson補外、2段階シンプレックス、PCA（Jacobi）、Varimax因子分析、Ward階層クラスタ、CART回帰木、Bootstrap CI。
4. 他に類を見ない領域: 微分方程式、数値最適化、線形代数、医学計算、表計算範囲関数、次元解析、科学法則自動計算。
